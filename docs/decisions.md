# 架构决策

## 2026-11-23：Cordis 装配与 Python 执行

选择 TypeScript 提供 Harness 插件、设置页、应用注册、宿主模型与 Credentials 接入，Python 承接 FPL 已有供应商与 CLI 协议。这样可以复用现有多模态实现，后续应用仍通过一个公开 Cordis Service 使用它们。

二者使用带版本握手的双向 JSON-RPC；Host 回调覆盖凭据、Harness LLM 和应用工具。Worker 在每个 profile 中单实例运行，用文件锁保护任务所有权，异步执行最多四个任务。本地 MLX 推理和安装由各自串行锁管理。

## 2026-11-23：独立状态与恢复

配置、任务、事件与资源元数据由独立 SQLite 管理。配置使用 revision CAS，请求使用应用、会话、request_id 和规范化输入指纹确定幂等。任务保存已选择的连接与模型快照；供应商返回任务编号和结果 URL 时立即持久化。

重启恢复使用供应商回执继续查询，未知提交结果保持可核对状态。资源先以内容哈希原子落盘，再写入元数据；分块导入支持位置核对和重复分块校验。运行目录归 Harness profile，应用归属与会话用于任务追踪。

## 2026-11-23：宿主 API 和设置页

使用显式 Typert 远程描述符，同时向 Host registry 注册调用定义、向 Client mount 注册消费接口。客户端在 `remote.dshCore` 的 Cordis 注入范围内调用。设置入口注册到原生 `settings.section`，客户端按 Harness 的惰性 module factory 格式打包，共用宿主 React。

通过安装包在真实 Harness 中发现并修正了上述 Host / Client 装配差异。Harness 代理环境同时包含 `::1` 和 `[::1]`，而 HTTPX 0.28 无法解析后者；Python 启动时将方括号 IPv6 绕过项规范化，其余代理配置保留，回归测试覆盖此环境。

## 2026-11-23：迁移与验证

供应商和 CLI 协议以自有包形式迁入，保留固定模型清单、安装校验、异步生成、CLI 工具白名单、过程取消和恢复规则。独立资源、配置与任务状态替代原网站存储装配。来源和文件适配见 extraction.json；协议夹具覆盖网络参数与失败，真实 FFmpeg、Codex 和 Harness 验证执行链。

## 2026-11-23：独立服务、FPL 看板与可选 DSH 连接层（当前）

用户选择复用已有 FPL 界面，并将运行生命周期从 DSH 中移出。本条替代前述“宿主启动执行层、profile 拥有业务状态、原生设置页管理全部能力”的装配决定；保留已迁入的协议、任务回执与资源实现。

Python 直接装配 HTTP/WS 和持久业务；看板采用 FPL 页面及其明确的协议子集；DSH 插件仅装配公开客户端、受限任务工具和宿主回调。使用现有仓库，不增加跨仓库运行依赖。配对身份限定应用范围；本机会话与供应商凭据由 Core 自有装配管理。

首次使用空配置，旧 profile 不做原地改写或导入。服务停止和 DSH 卸载分属不同生命周期。已知供应商回执继续查询；连接断开后的未知付费调用不重放。正式服务运行包包含 Python 源码、锁定依赖说明、已构建看板和启动器，不引用 FPL 或 `.local/`。

对比过仅移动设置页、先转发 FPL 后端和整套工坊同时迁移。用户选择第一阶段只交付独立公共能力，以现有页面为视觉和交互基线，随后逐个迁入业务应用。

验证使用原协议套件、独立 HTTP 与连接层测试，以及真实页面的配置、SSE、刷新恢复、日志、资源、配对和多视口验收。结果与覆盖限制在 verification.md 记录。

## 2026-11-23：凭据提交与运行恢复

供应商凭据使用 Core 自有密钥加密，密文与目录和执行连接在同一 SQLite 事务提交，避免目录更新而凭据写入失败的分裂状态。凭据读取经显式注入的 ProviderCredentials 完成。分块上传预先固定资源 ID，完成回执持久化；回执响应丢失或提交中断时重试返回同一资源。

启动器用运行目录锁和实例标识验证所有权；同一运行目录不允许同时占用多个端口。端口检查使用与监听器一致的地址复用选项，避免停止后 TCP 等待状态误报占用。独立运行包通过并发启动、端口冲突和立即重启验证，不依赖临时源码目录。

## 2026-11-23：运行记录与智能体测试分工

任务持久化继续由 Core 拥有，界面将其呈现为 AI 能力下的“运行记录”，首页只展示最近运行。独立任务一级菜单和在该页创建智能体测试的方式混合了执行观察与能力测试，空页面缺少价值，因此智能体测试回到所选编程智能体的连接页面；提交回执提供本次运行详情链接。

运行记录支持来源与状态组合筛选，区分模型测试、智能体测试、本地模型管理和插件应用；插件停用后仍保留任务的应用标识。详情同时呈现已有输出和错误，允许显式取消和已有回执的结果恢复，不创建重试任务。模型对话来源链接携带会话标识，来源删除后保留运行输出。旧 /tasks 地址继续兼容。

本次只调整看板组合和展示，不改变公开执行请求、持久数据或付费调用恢复语义。验证覆盖筛选、详情链接、取消和恢复操作、智能体测试提交及错误反馈，以及明暗主题和宽窄屏。

## 2026-11-23：保留应用界面，由 DSH 插件供给目录

此前仅交付公共能力页面时裁掉了应用区，与用户后续通过 DSH 插件安装应用的目标不符。恢复首页四分类文件夹与应用入口，复用 FPL 文件夹几何和应用卡片样式。应用目录由已配对连接上的插件发布；应用名称、分组、图标、版本和本机页面入口经过校验并独立持久保存。

选择扩展现有 registerApplication 的可选 dashboard 字段，保留原任务调用方兼容。考虑过硬编码原工坊条目和仅展示在线应用；采用实际插件登记、断线状态及重连完整快照，使卸载/停用及时反映且不会把未安装业务显示为可用。应用页面在自己的本机入口运行，Core 只提供目录与公共能力。

文件上传原先将 label 当按钮使用，缺少按钮盒模型且图标按基线排版。改用原生按钮触发文件选择器，并给图标与文本统一的 flex 对齐；浏览器验收检查二者中心、键盘激活、浅深色及不同窗口宽度。

验证覆盖真实连接层登记、重连、卸载、离线和不可信入口地址拒绝；隔离 Harness 安装验证应用元信息实际到达看板 API。

## 2026-11-23：复用集成中心与双向独立配置副本（0.3.0）

### Problem

独立 Core 缺少原 FPL 的集成管理；DSH 插件已有的 MCP、Skill 和外部服务配置需要便捷复用。单独的 DSH 外部连接页又和集成中心重复，且两个大配对区域与逐项服务卡片的样式不一致。

### Decision

迁入原四类页面及其协议闭包，由 Core 自有库、身份、迁移、加密和执行回执装配。外部连接统一逐项卡片，DSH 配对与飞书配置使用同一套弹窗、按钮和状态；旧地址跳转兼容。DSH 连接层只使用公开的配置/Skill API 及显式插件适配器，导入内容由 Core/DSH 各自独立保存，默认停用。

配置复制采用加密快照、revision CAS、来源映射、逐项持久回执与未知结果查询；不做自动双向同步。Skill 完整复制附件与独立版本，同名新副本同步修改 frontmatter。配置检查和显式工具调用归 Core 运行记录，重启不自动重放。DSH 导入副本使用 profile 自有的加密文件与 Credentials 密钥，与原生配置分开，明确启用后才登记工具和 Skill。

### Alternatives considered

考虑过仅恢复菜单、直接读取 FPL 数据库、改写第三方 profile YAML，以及自动双向同步。前者没有真实行为；跨私有存储或猜测配置增加更新耦合；自动同步会覆盖另一端修改。选择公开适配器和独立副本，代价是第三方需要实现导出/导入边界，暂不能完整取得附件的 Skill 明确拒绝。

### Consequences

Core 和连接器升级仍可分别进行；旧连接器保持原功能，新导入需要 0.3.0 连接器。凭据在确认复制时进入目标自有存储，预览与回执不回显。迁移只新增 Core 自有集成库；原配置、应用目录和运行记录保留。正式恢复依赖集成库、文件、Core state/access 和 DSH Credentials，不能只保留其中一个密文文件。

### Verification

验证覆盖四类目录、脱敏、revision、完整附件、源变化、部分失败、目标修改、同名 Skill 与断线后的原回执查询；真实 stdio MCP、工具 API 夹具、真实 Chrome 四标签/双向导入/逐项连接列表与明暗及三种窗口宽度。完整结果见 verification.md。

## 2026-11-23：为独立工坊提供完整生成参数目录

视觉工坊接入真实 Core 时发现，最小连接目录缺少尺寸与工作流约束，模型测试页又为所有图片模型给出固定 1024px 选项，导致 Seedream 的合法请求在入队时被拒绝。新增 Core 拥有的只读生成目录，复用已迁入供应商协议的参数定义；看板与配对应用共用此接口，避免应用各自猜测。目录过滤未支持的模型组合，同时保留执行端的独立校验，不更改任务、凭据和迁移状态。

接口按字段增量兼容，独立工坊要求 0.3.1 的 generation-catalog 能力。验证覆盖 Seedream 尺寸、Seedance 引用限制、工作流参数、音频模型及密钥不出目录，并通过真实 Core / 应用联调。最终验收结果同步 verification.md。

## 2026-11-23：连接器使用宿主提供的 DSH 公共接口

桌面 0.2.2 实装发现，连接器将 dsh-host-plugin-inventory 0.2.1 作为普通依赖带入 profile，包解析会使宿主本身加载旧库存插件，从而让新版插件页的 pluginInventory/list 返回 404。dsh-mcp-client 同样属于宿主公共能力。两者改为可选 peerDependency，并在开发依赖中保留固定版本用于构建和隔离验收，运行时由 DSH 提供，不将旧宿主实现安装到用户 profile。其余任务、模型与凭据协议不变。

本机安装使用独立安装包，通过正常插件管理更新；配对使用公开 RPC。验证检查桌面库存接口、三个插件启用状态、两个工坊的独立服务与 Core 登记，以及原连接层测试。


## 2026-11-23：四工坊独立迁移与 Core 统一账号（0.4.0）

用户选择完整迁入演示、思绪、Galgame 和录音标注，思绪包括社区、逐篇授权、官方显式导入与飞书同步；同时由 Core 提供统一账号。采用独立仓库和运行服务，保留原业务、界面、CAS 与任务恢复语义。Core 管账号、供应商密钥、公共任务资源和外部同步，DSH 仅登记并调用公开工具。原 FPL 服务、数据和受保护产品文档不改动。

考虑过每个应用继续本机 owner 登录和网站数据库转发；前者不能统一撤权，后者让克隆后的应用依赖旧网站。选择 Core 一次性授权码和后端持续身份核验。旧视觉/剪辑应用仅将初始 Core UUID 投影到原 owner ID，保留旧项目与生成账本；新账号持有独立桥接、会话和任务账本。供应商/机器执行权限按账号校验，管理员也不能直接读取另一个账号的私人数据。

跨应用交接通过 Core 签发的精确短期授权和目标自有存储复制，保留剪辑片段的既有不可变清单和任务幂等。思绪飞书同步采用 Core 拥有的公开步骤 API，先落意图与请求回执，未知写入结果不重放。官方知识包仅复制来源文件，首次启动不自动写入新库。

验证含独立克隆环境的测试与构建、七个真实进程的公开 CLI/HTTP/WS、两账号隔离、原生 PPTX、真实 FFmpeg 原件交接、Core 模型任务、飞书协议闭环、真实 Chrome 与实际 Harness tarball。模型/飞书网络替换为确定性夹具，真实付费供应商不在本次验收范围。完整结果见 verification.md。

## 2026-11-23：移除看板运行记录

用户不再需要独立运行记录功能。本条替代前述运行记录页面、首页最近运行及任务详情链接的展示决定：移除对应导航、路由、列表、筛选与详情组件，旧 `/tasks` 地址按未知页面规则回到首页。智能体测试直接在原页面显示本次结果、错误、停止和恢复查询，避免留下失效链接；离开页面后不提供独立历史入口。

仅移除菜单会留下首页和直接地址入口，故一并移除完整看板功能。Core 的任务 API、幂等回执、持久状态和执行恢复仍是模型与应用依赖的公共契约，继续保留。界面不再在首页轮询所有任务。验证覆盖旧地址、首页和导航无入口，以及智能体测试输出、取消失败重试和结果查询。


### 全新克隆的 Node 构建策略

pnpm 工作区显式允许锁定的 esbuild 0.27.7 安装校验；protobufjs 7.6.6 的非编译安装钩子明确禁用。首次安装不依赖开发机器过去的审批或 node_modules 缓存，不放行其他未声明脚本。


### 独立服务与 DSH 的重复登记

同一应用会由独立账号桥接和 DSH 工具连接同时登记。看板按包和入口 URL 合并为一张卡片，优先使用 ready 登记，保留全部登记 ID 对应的旧详情链接；后端协议仍保留每条真实登记。关闭 DSH 后直接服务的应用入口继续可用，首页分类和应用列表使用同一投影。


### DSH 后台账号目录

思绪私有知识库也需要查询作者的公开账号值；DSH 工具没有浏览器会话。Core 的应用后端目录允许用已验证 client secret 和明确 owner_user_id 查询，实时验证该账号仍启用且仍授权此应用，只返回公开账号值，不生成用户会话、不开放 Core 私有配置。浏览器仍使用原一次性 code 与应用 session；社区发布等交互权限继续由思绪原契约控制。新增纯插件凭据读取与账号撤权回归。


## 2026-11-24：统一存储与来源快照

采用路径型机器定位合同与各提供方维护入口。Core 协调计划、停写、恢复和提交检查点；工坊拥有自己的 schema、数据映射及文件导入。拒绝直接访问其他应用数据库。选择独立 COW/有界复制和逐文件摘要，保留原目录；模型解释器重建。主要来源账号映射必须明确，其他账号隔离。DSH 列表标题统一采用 dsh-fpl- 前缀，稳定注册标识及配对继续沿用。接口、失败恢复和操作见 [存储迁移](storage.md)。


## 2026-11-24：插件开关默认启停服务（0.5）

用户明确选择开关控制完整启停，本条替代此前连接器不管理进程、关闭后继续常驻的默认安排。提供方保留正式启动器和业务存储，Core 提供仅本机 Node 生命周期接口，默认关闭先停工坊再停 Core。manageService=false 为显式常驻模式。安装描述只保存路径，serviceDirectory 可覆写；不在插件安装时下载环境或隐式初始化其他应用。OS 锁、进程归属、维护门禁、失败回退和真实退出共同约束快速启停。

七服务真实包验收发现 Cordis 会将可构造的普通函数作为类入口；返回异步生成器时不会执行其生命周期。工坊入口改为不可构造函数，Core 使用异步生成器入口，确保框架等待启动、收集回退并等待停机。


## 2026-11-24：恢复原版文件管理界面与 Core 自有编辑能力

### Problem

Core 使用简化资源卡片承载迁入目录，文件夹误用 160px 预览容器并按行内基线排列；原版文件库的紧凑列表、视图切换、筛选排序和管理操作没有迁入。只修卡片对齐不能恢复用户已有的文件管理方式。

### Decision

复用 FPL 原版浏览器的三份样式和条目结构，默认紧凑列表，提供列表/网格、搜索、类型、排序、统计、路径与分页。界面按浏览、预览、编辑、传输职责组织，所有数据经 Core 自有 API，来源摘要记录于 ui-extraction.json，无 FPL 运行依赖。

Core 在现有账号文件库的 metadata 中保存显示名、revision、更新时间和移除标记，保持原资源字节和资源接口不可变。编辑以短事务核对 revision、目录归属、同名和循环；删除只接受空目录。文件移除明确为从文件管理隐藏，保留工坊引用。历史记录缺失时间显示未知，不伪造最近更新。

导入在写入前校验完整路径集合和数量/大小，按请求 UUID、内容摘要和目标保存回执，使用确定性资源及目录标识恢复逐文件提交。失败保留已成功内容，浏览器先查询回执，用户显式重新选择同一输入才继续。ZIP 导出在账号运行目录的临时文件中流式构建并校验原件摘要，响应结束关闭；不复制持久恢复点、不改迁移 schema 或账本。

### Alternatives considered

考虑过只调整大卡片、让 Core 直接调用 FPL 素材库和将显示名写回原资源。前者不能恢复原界面；跨服务私有依赖破坏独立运行；重写原资源会影响既有任务和迁移回执。选择迁入展示层、Core 自有协议和独立库条目元数据，代价是文件管理移除不回收仍可能被引用的原件。

### Consequences

文件夹在网格中保持 72px 的紧凑条目，文件使用缩略图；列表保留名称、类型、大小和时间。图片/SVG、视频、音频、PDF、文本可预览，Office 等未接入转换器的格式下载查看。SVG/PDF 保留原内容入口的附件策略，采用有界 Blob 预览，不内联执行文档；前端取消读取和关闭弹窗时释放对象 URL。操作菜单提升所在条目的层级，避免窄屏网格中被后续卡片遮挡。

### Verification

隔离接口测试覆盖账号隔离（含管理员）、CSRF、版本冲突、同名和循环目录、空目录删除、分页/搜索/筛选、移除后原件保留、显示名下载、ZIP/目录往返、请求重用与中断续传、非法路径及导入上限。真实 Chrome 检查明暗主题和 1920/800/390px 的两种视图，以及预览、文件选择器、编辑、移除、ZIP/目录导入和 ZIP 下载。完整结果见 verification.md。

## 2026-11-24：包内服务与宿主安装控制

保留独立 Python 服务的业务所有权。npm 插件携带提供方自己的生产载荷、锁文件与编译界面，以 SHA256 清单标识内容，不能发布本机路径描述、虚拟环境、数据或私人品牌资源。Core 连接层提供服务安装控制面，使服务不存在时仍可打开安装向导；只通过公开 CLI 启停、配置授权，不直接改其他插件数据库。默认安装路径与业务数据分开；已有外部服务模式继续支持。首轮仅支持 macOS，Apple Silicon 实测，Intel 仅做静态载荷检查。

账号授权由已认证 Core 浏览器批准，Host 持有独立领取证明；私有回执通过提供方 CLI 写入自己的配置，重复领取可恢复，不自动转移账号归属。工具从提供方公开 OpenAPI 白名单生成，Host 使用兼容的 schema 子集展示，执行前后仍按完整 schema 校验；文件采用有界临时文件与分块 Core 资源流。供应商付费调用在验收中用提供方公开夹具模拟，不将模拟结果表述为真实供应商验收。候选不发布、不更新总仓库 gitlink；正式版本另行分配并按载荷摘要复验。

## 2026-11-24：应用身份与外部连接分别展示

工坊独立服务与 DSH 宿主共用桥接协议，不能据此把所有桥接标成 DeepSeek Harness。Core 的桥接列表新增只读 `kind` 与可空 `application_id`，按当前账号持久的应用身份绑定分类；旧配对无绑定时保持 DSH 类型。名称、在线状态和 dashboard 登记不参与判断，因此断线与重启不会改变应用归属，也不需要迁移既有配对或凭据。

外部连接只展示和计数 DSH 配对与第三方服务；工坊入口和状态沿用应用目录。顶部 DSH 状态只统计在线的 DSH 类型。完整桥接 API 继续返回两种身份，保留原有配对、撤销和应用协议。隔离接口测试覆盖同名、断线、撤权、重启与账号边界；Chrome 验证应用仍可打开、外部连接不包含应用，以及仅应用在线时顶部不报 DSH 已连接。


## 2026-11-24：移除 SenseAudio 供应商适配

按用户要求移除七类供应商适配、目录入口及实时语音浏览器实现。方舟、ZEALMAN 和 AutoDL 继续使用迁入供应商无关模块的任务状态与错误脱敏工具。通用能力标识及实时语音兼容接口保留，接口明确返回空目录或能力不可用；不会把不存在的实现列为可用能力。

旧配置由 Core 在账号锁内、任务恢复前事务清理，失败回滚并拒绝启动，重复启动不增加目录版本。历史任务、日志、会话和素材保留，已受理但未完成的供应商任务标记中断，保留回执供核对，禁止自动及手动恢复。导入旧目录跳过退役供应商和其密钥，历史日志仍脱敏，历史供应商类型作为不参与执行的字符串保存。来源审计清单保持原始记录。

隔离测试覆盖退役类型拒绝、配置与专属密钥清理、共享密钥、账号隔离、事务回滚、幂等和任务恢复拦截。当前能力与兼容接口见 scope.md 和 api.md；组合验收结果记录于总工作区。
