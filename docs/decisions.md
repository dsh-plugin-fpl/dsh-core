# 架构决策

## 2026-11-23：Cordis 装配与 Python 执行

选择 TypeScript 提供 Harness 插件、设置页、应用注册、宿主模型与 Credentials 接入，Python 承接 FPL 已有供应商与 CLI 协议。这样可以复用现有多模态实现，后续应用仍通过一个公开 Cordis Service 使用它们。

二者使用带版本握手的双向 JSON-RPC；Host 回调覆盖凭据、Harness LLM 和应用工具。Worker 在每个 profile 中单实例运行，用文件锁保护任务所有权，异步执行最多四个任务。本地 MLX 推理和安装由各自串行锁管理。

## 2026-11-23：独立状态与恢复

配置、任务、事件与资源元数据由独立 SQLite 管理。配置使用 revision CAS，请求使用应用、会话、request_id 和规范化输入指纹确定幂等。任务保存已选择的连接与模型快照；供应商返回任务编号和结果 URL 时立即持久化。

重启恢复使用供应商回执继续查询，未知提交结果保持可核对状态。资源先以内容哈希原子落盘，再写入元数据；分块导入支持位置核对和重复分块校验。运行目录归 Harness profile，应用归属与会话用于任务追踪。

## 2026-11-23：宿主 API 和设置页

使用显式 Typert 远程描述符，同时向 Host registry 注册调用定义、向 Client mount 注册消费接口。客户端在 `remote.dshCore` 的 Cordis 注入范围内调用。设置入口注册到原生 `settings.section`，客户端按 Harness 的惰性 module factory 格式打包，共用宿主 React。

通过安装包在真实 Harness 中发现并修正了上述 Host / Client 装配差异。Harness 代理环境同时包含 `::1` 和 `[::1]`，而 HTTPX 0.28 无法解析后者；Python 启动时将方括号 IPv6 绕过项规范化，其余代理配置保留，回归测试覆盖此环境。

## 2026-11-23：迁移与验证

供应商和 CLI 协议以自有包形式迁入，保留固定模型清单、安装校验、异步生成、CLI 工具白名单、过程取消和恢复规则。独立资源、配置与任务状态替代原网站存储装配。来源和文件适配见 extraction.json；协议夹具覆盖网络参数与失败，真实 FFmpeg、Codex 和 Harness 验证执行链。

## 2026-11-23：独立服务、FPL 看板与可选 DSH 连接层（当前）

用户选择复用已有 FPL 界面，并将运行生命周期从 DSH 中移出。本条替代前述“宿主启动执行层、profile 拥有业务状态、原生设置页管理全部能力”的装配决定；保留已迁入的协议、任务回执与资源实现。

Python 直接装配 HTTP/WS 和持久业务；看板采用 FPL 页面及其明确的协议子集；DSH 插件仅装配公开客户端、受限任务工具和宿主回调。使用现有仓库，不增加跨仓库运行依赖。配对身份限定应用范围；本机会话与供应商凭据由 Core 自有装配管理。

首次使用空配置，旧 profile 不做原地改写或导入。服务停止和 DSH 卸载分属不同生命周期。已知供应商回执继续查询；连接断开后的未知付费调用不重放。正式服务运行包包含 Python 源码、锁定依赖说明、已构建看板和启动器，不引用 FPL 或 `.local/`。

对比过仅移动设置页、先转发 FPL 后端和整套工坊同时迁移。用户选择第一阶段只交付独立公共能力，以现有页面为视觉和交互基线，随后逐个迁入业务应用。

验证使用原协议套件、独立 HTTP 与连接层测试，以及真实页面的配置、SSE、刷新恢复、日志、资源、配对和多视口验收。结果与覆盖限制在 verification.md 记录。

## 2026-11-23：凭据提交与运行恢复

供应商凭据使用 Core 自有密钥加密，密文与目录和执行连接在同一 SQLite 事务提交，避免目录更新而凭据写入失败的分裂状态。凭据读取经显式注入的 ProviderCredentials 完成。分块上传预先固定资源 ID，完成回执持久化；回执响应丢失或提交中断时重试返回同一资源。

启动器用运行目录锁和实例标识验证所有权；同一运行目录不允许同时占用多个端口。端口检查使用与监听器一致的地址复用选项，避免停止后 TCP 等待状态误报占用。独立运行包通过并发启动、端口冲突和立即重启验证，不依赖临时源码目录。

## 2026-11-23：运行记录与智能体测试分工

任务持久化继续由 Core 拥有，界面将其呈现为 AI 能力下的“运行记录”，首页只展示最近运行。独立任务一级菜单和在该页创建智能体测试的方式混合了执行观察与能力测试，空页面缺少价值，因此智能体测试回到所选编程智能体的连接页面；提交回执提供本次运行详情链接。

运行记录支持来源与状态组合筛选，区分模型测试、智能体测试、本地模型管理和插件应用；插件停用后仍保留任务的应用标识。详情同时呈现已有输出和错误，允许显式取消和已有回执的结果恢复，不创建重试任务。模型对话来源链接携带会话标识，来源删除后保留运行输出。旧 /tasks 地址继续兼容。

本次只调整看板组合和展示，不改变公开执行请求、持久数据或付费调用恢复语义。验证覆盖筛选、详情链接、取消和恢复操作、智能体测试提交及错误反馈，以及明暗主题和宽窄屏。

## 2026-11-23：保留应用界面，由 DSH 插件供给目录

此前仅交付公共能力页面时裁掉了应用区，与用户后续通过 DSH 插件安装应用的目标不符。恢复首页四分类文件夹与应用入口，复用 FPL 文件夹几何和应用卡片样式。应用目录由已配对连接上的插件发布；应用名称、分组、图标、版本和本机页面入口经过校验并独立持久保存。

选择扩展现有 registerApplication 的可选 dashboard 字段，保留原任务调用方兼容。考虑过硬编码原工坊条目和仅展示在线应用；采用实际插件登记、断线状态及重连完整快照，使卸载/停用及时反映且不会把未安装业务显示为可用。应用页面在自己的本机入口运行，Core 只提供目录与公共能力。

文件上传原先将 label 当按钮使用，缺少按钮盒模型且图标按基线排版。改用原生按钮触发文件选择器，并给图标与文本统一的 flex 对齐；浏览器验收检查二者中心、键盘激活、浅深色及不同窗口宽度。

验证覆盖真实连接层登记、重连、卸载、离线和不可信入口地址拒绝；隔离 Harness 安装验证应用元信息实际到达看板 API。

## 2026-11-23：复用集成中心与双向独立配置副本（0.3.0）

### Problem

独立 Core 缺少原 FPL 的集成管理；DSH 插件已有的 MCP、Skill 和外部服务配置需要便捷复用。单独的 DSH 外部连接页又和集成中心重复，且两个大配对区域与逐项服务卡片的样式不一致。

### Decision

迁入原四类页面及其协议闭包，由 Core 自有库、身份、迁移、加密和执行回执装配。外部连接统一逐项卡片，DSH 配对与飞书配置使用同一套弹窗、按钮和状态；旧地址跳转兼容。DSH 连接层只使用公开的配置/Skill API 及显式插件适配器，导入内容由 Core/DSH 各自独立保存，默认停用。

配置复制采用加密快照、revision CAS、来源映射、逐项持久回执与未知结果查询；不做自动双向同步。Skill 完整复制附件与独立版本，同名新副本同步修改 frontmatter。配置检查和显式工具调用归 Core 运行记录，重启不自动重放。DSH 导入副本使用 profile 自有的加密文件与 Credentials 密钥，与原生配置分开，明确启用后才登记工具和 Skill。

### Alternatives considered

考虑过仅恢复菜单、直接读取 FPL 数据库、改写第三方 profile YAML，以及自动双向同步。前者没有真实行为；跨私有存储或猜测配置增加更新耦合；自动同步会覆盖另一端修改。选择公开适配器和独立副本，代价是第三方需要实现导出/导入边界，暂不能完整取得附件的 Skill 明确拒绝。

### Consequences

Core 和连接器升级仍可分别进行；旧连接器保持原功能，新导入需要 0.3.0 连接器。凭据在确认复制时进入目标自有存储，预览与回执不回显。迁移只新增 Core 自有集成库；原配置、应用目录和运行记录保留。正式恢复依赖集成库、文件、Core state/access 和 DSH Credentials，不能只保留其中一个密文文件。

### Verification

验证覆盖四类目录、脱敏、revision、完整附件、源变化、部分失败、目标修改、同名 Skill 与断线后的原回执查询；真实 stdio MCP、工具 API 夹具、真实 Chrome 四标签/双向导入/逐项连接列表与明暗及三种窗口宽度。完整结果见 verification.md。

## 2026-11-23：为独立工坊提供完整生成参数目录

视觉工坊接入真实 Core 时发现，最小连接目录缺少尺寸与工作流约束，模型测试页又为所有图片模型给出固定 1024px 选项，导致 Seedream 的合法请求在入队时被拒绝。新增 Core 拥有的只读生成目录，复用已迁入供应商协议的参数定义；看板与配对应用共用此接口，避免应用各自猜测。目录过滤未支持的模型组合，同时保留执行端的独立校验，不更改任务、凭据和迁移状态。

接口按字段增量兼容，独立工坊要求 0.3.1 的 generation-catalog 能力。验证覆盖 Seedream 尺寸、Seedance 引用限制、工作流参数、音频模型及密钥不出目录，并通过真实 Core / 应用联调。最终验收结果同步 verification.md。

## 2026-11-23：连接器使用宿主提供的 DSH 公共接口

桌面 0.2.2 实装发现，连接器将 dsh-host-plugin-inventory 0.2.1 作为普通依赖带入 profile，包解析会使宿主本身加载旧库存插件，从而让新版插件页的 pluginInventory/list 返回 404。dsh-mcp-client 同样属于宿主公共能力。两者改为可选 peerDependency，并在开发依赖中保留固定版本用于构建和隔离验收，运行时由 DSH 提供，不将旧宿主实现安装到用户 profile。其余任务、模型与凭据协议不变。

本机安装使用独立安装包，通过正常插件管理更新；配对使用公开 RPC。验证检查桌面库存接口、三个插件启用状态、两个工坊的独立服务与 Core 登记，以及原连接层测试。
