# 安装与连接

本轮是 macOS 未发布候选，主验收使用本机桌面安装内置的 DSH 0.2.2-rc.1 和 Node 24.21.0 的隔离副本，npm 0.2.2-rc.5 仅作额外兼容检查。终端全局 dsh 版本不作为桌面版本依据。Core 与六个工坊仍是独立服务。一个插件的安装包只含它自己拥有的源码、生产依赖锁文件与编译后的界面，不携带环境、账号、资源或开发机路径。

## 首次使用

1. 在 DSH 中启用 Core 与所需工坊，打开设置 → FPL 安装与连接。
2. 先安装 Core，再安装工坊。安装会联网准备 uv（本机缺失时）与固定 Python 3.13.15，用锁文件创建隔离生产环境。
3. 打开 Core 看板确认当前账号。回到向导选择工坊，发起授权，在 Core 页面检查来源与服务地址后批准，再回向导完成连接。
4. 查看就绪状态，再使用原生工具或独立看板。视频等媒体功能另需 FFmpeg 和 ffprobe，可按 [FFmpeg 官方下载说明](https://ffmpeg.org/download.html) 安装后重试。

## 安装、修复和恢复

默认环境根目录是 `~/Library/Application Support/DSH-FPL-Runtime/.runtime`。`DSH_FPL_RUNTIME_ROOT` 可设为其他正式绝对路径，不允许 `.local`。每个服务按载荷摘要保存代码、独立虚拟环境、私有日志与安装记录。数据根目录沿用公开统一存储定位配置；没有配置时默认 `~/Library/Application Support/DSH-FPL`，可用 `DSH_FPL_DATA_ROOT` 设置。已登记但不可用的存储盘不会自动替换成空目录。

“检查 / 修复环境”校验载荷并重建环境，不改变数据归属。失败时保留旧记录，尽力恢复旧服务；取消会先终止安装进程再清理未激活目录。断网、摘要错误、端口占用等通过错误码与私有日志定位后可重试。同一个服务有跨进程安装锁，不能同时安装两份。关闭 Core 时先停止托管工坊；外部服务模式继续独立运行。

生命周期锁使用运行目录中的独立托管 Python，Core 停服入口只依赖标准库。因此虚拟环境中的解释器丢失时，仍可先正常停服再重建；不通过强杀跳过所属实例校验。

`serviceDirectory` 明确指定已有独立服务目录；`manageService=false` 只连接，不执行安装、停止或接管。旧本机路径描述仍可读取，新候选包不再生成。不要将构建候选目录当作正式业务数据位置。

## 接口和权限

安装状态接口属于 Core 连接层 `invoke` 的 `setup.*` 方法，仅 Harness 所有者可调用。浏览器可见的授权摘要不含密钥；Host 用随机证明领取短期加密回执。`POST /v1/setup/authorizations` 创建请求，已认证且通过 CSRF 校验的 Core 页面批准，`exchange` 校验领取证明。重复领取返回同一回执；撤销账号授权后不能继续领取。首次登记工坊需管理员授权，已有应用地址或账号不符会停止并要求显式恢复。

工坊通过自己的 `connect-core --authorization-file` CLI 消费 0600 普通文件，在线核验 Core 账号后只写自己的配置。没有旧身份凭据时不自动接管已登记的客户端。授权回执不应上传、粘贴到日志或提交。

六个工坊公开导出 `native-tools.json`。Core 将完整 schema 转换为两代 Host 支持的子集展示，并在执行前后使用完整契约校验；原公开 request/describe 工具保持兼容。文件传输使用有界临时文件、SHA256 与 Core 分块接口，默认最大 256 MiB；旧 Core 的非流式导入兼容仅允许 8 MiB。超时或取消后应按已有任务回执核对结果，不重放未知结果的付费调用。

## 验收边界

Apple Silicon 运行两个目标 Host；Intel 校验载荷平台、uv 下载地址和摘要，不代表完成 Intel 实机验收。独立业务与界面采用真实服务、HTTP/WS、FFmpeg 和 Chrome；模型与外部账号采用提供方公开测试夹具。正式发布前必须分配新版本、同步最小 Core 依赖与锁文件，并对最终 tarball 重跑验收。此文不授权发布、提交或推送。
